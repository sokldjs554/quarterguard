## 4. 비교 실험과 실행 근거

[리랭킹 실험](ranking-v2.md): 같은 후보의 개발36질의에서 혼합 Recall@1 1.000→cross encoder0.806, MRR@5 1.000→0.903, p50 1.52→149.47ms. 마지막6개 정답 질의에서는4/6→5/6이지만 단어 검색6/6보다 낮다. 고정180자와 문맥 셀의 정보량 차이, CPU·캐시 조건을 명시한다. fixture 검색 실험이며 PDF 추출 성능이 아니다. 문맥 필터를 리랭커라고 부르지 않는다.

[MCP 검사](mcp-v2.md): 실제8개 흐름·5개 직접 오류 입력과 모의 전송/시간초과/잘못된 응답을 구분한다. 실패 뒤 이전 성공을 새 결과로 돌려주지 않는다. [DART 개인 테스트](code-review-kit/review-dart-20261109.md)는 단위 환산·금액 오류·중복 후보 거부를 fixture로 확인한3개이며 새로운 DART 호출이 아니다. [기간 개인 테스트](code-review-kit/review-20261108.md)는 같은3개월이라도 비인접 QoQ를 보류하고 전년 YoY는 허용하는2개다.

## 5. 지원서에 쓸 문장

> AI 코딩 도구를 활용해 금융 공시의 원문 근거와 비교 조건을 확인하는 QuarterGuard를 개발했습니다. 새 연도 PDF의 파싱 실패를 보완하고 원문 파싱과 fixture 평가를 구분했으며, 청킹·임베딩·실제 리랭커를 비교해 악화된 결과도 공개했습니다. 직접 기간·DART 방어 테스트5개를 보강·실행했고, 이후 기간 진단과 실제 도구 실행 이력을 구분하는 설명 코드를 수정했습니다. 금융 분야 경력3년인 지인의 사용 의견을 반영해 화면을 개선했으며, 실제 LLM 응답의 구조·인용 검사와 사람의 설명 판정을 분리해 기록했습니다.

면접에서 덧붙일 수치: “같은 개발16건의 구조 일치가8/16에서16/16으로 바뀌었지만 설명은 참15·모호1이어서, 구조 통과가 의미 정확성 보장은 아니었습니다.”

독립 개발·AI 도움 없음, 본인이 모든 오류를 최초 발견, 금융기관 고객 배포, 회사 공식 검수, 자율 LLM 에이전트, 일반 정확도100%, 작업시간 단축률을 주장하지 않는다. b는 금융 분야 친구1명이며 후속 검수를 새 참가자로 세지 않는다.

## 6. 지금 남은 일과 선택적 후속

지원 준비의 다음 행동은 [5분 시연·면접 체크](application-demo-guide-20261110.md)다. 추가 테스트1개의 diff는 수신·통합해 수량 차이를 해소했다. 본인 환경에서 건너뛴 항목 이름은 미제공으로 유지한다. 실제 기기·브라우저에서 현재 데모를 확인하고 접속 실패가 있으면 그대로 남긴다. AI 검사로 본인 수행을 대신 기록하지 않는다.

별도 후속 연구는 수정에 쓰지 않은 질의/문서·독립 검수자 확대, 내부 코드 잔존·부정문 오차단·비교 방향 문구 보완이다. 전부 지원 전에 반복해야 하는 필수 단계는 아니다. 유료 호출은 구체적 비용 범위 승인 후에만 실행한다. 실제 고객 환경 기회가 생기면 [접근·자료·배포 허가 확인표](validation-kit/customer-access-checklist.md)를 사용하며 현재 고객 배포0건을 유지한다.

기준 코드의 검증은 [PR #45](https://github.com/sokldjs554/quarterguard/pull/45)에서 확인한다: GitHub/Render/공개health 커밋 일치, CI 성공, AI Python238개(1개 건너뜀)·Node14개·로컬 브라우저10개, TLS 검증 중계9GET200. 직접Chromium HTTPS는 인증서 오류다. 이 수치는 문서 통합 커밋에서 새로 실행한 검사 수가 아니다.
