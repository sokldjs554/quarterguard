# v9 새 생성 효과 평가 — 승인 전 준비

기준 제품 커밋: `aafbbbd8a3e52f6ce537e66e5244baccb95eeb61`.
목적: 비교 방향, 근거 부재 부정문, 내부 표현에 대한 새 프롬프트로 실제 응답을 다시 생성하고 v8과 같은 현재 검사 기준으로 비교한다. 제품 코드는 이번 준비에서 변경하지 않는다.

## 실행 계약

- 모델: `gpt-5.4-mini-2026-03-17`, reasoning none.
- 기존 삼성·현대 입력16개, 최대16회, 재시도0. 첫 API/응답 오류 시 중단한다.
- 회당 입력 사전 상한8500(직렬화 요청 UTF-8 바이트수 +1024 여유분으로 보수적으로 제한; API 입력 하드캡 아님), 출력 상한700토큰, 요청 시간제한60초.
- 기록된 공개 단가 입력 $0.75/백만, 출력 $4.50/백만 기준 최대 추정 **$0.1524**, 예산 **$0.16**, 세금·환율 제외. 단가 확인 기록은2026-11-10, 실제 청구액 미조회.
- 기존 Actions `OPENAI_API_KEY` 재사용. 새 배치에 대한 구체적 승인을 받은 뒤에만 workflow_dispatch한다. 과거 승인/실행과 별개다.
- 재실행·중복 dispatch를 키 노출 전에 거부한다. 출력은 새 경로에서만 생성하고 실패한 시도도 보존한다.

## 비교 설계와 한계

동일16개는 모두 이미 공개되고 수정에 사용된 개발용 사례다. 새 독립 평가셋이나 사람 작성 사례로 바꾸어 표현하지 않는다. 기존 저장 도구 결과를 재사용하며 이번 배치에서 새 PDF 파싱·검색·MCP 실행은 하지 않는다. 일부 잘못된 초안 유도도 기존 AI 작성 입력 그대로다.

v8 원응답/당시 검사/b 판정은 유지한다. v8와 v9를 모두 새 검사로 평가해 프롬프트 변경과 검사 변경을 혼동하지 않는다. 거부 응답도 원문 그대로 저장해 b 검수에 포함한다. 자동 통과율과 사람 문장 판정은 분리한다. 한 번씩 생성하므로 일반화·통계적 개선을 보장하지 않는다. 평가 모델은 공개 제품 GPT-4.1 mini와 다르다.

## b 검수

[검수 양식](validation-kit/llm-prose-v9-review-20261111.md)을 사용한다. 새 응답이 생기면 원응답, 구조 필드, 도구 결과, 원문 URL/쪽/행/열을 묶어 전달한다. 먼저 새 문장을 판단하고 나중에 이전 응답과 자동 판정을 비교한다. AI가 사람의 판정·날짜·참여 결과를 채우지 않는다. 기존 b의 후속 참여이며 인원 추가0명이다.

현재 상태: **실제 호출0회, 생성0건, 새 사람 검수0건**. 준비된 입력 해시: `786cdc9814e42563ba707009b540458c67ca5dcf9f5079af8d7cc08d5f97947c`.
최대 실제 사전 입력 추정: 8008 (상한8500 이하).
