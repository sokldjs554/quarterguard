# 작성자 직접 코드 검토 준비 키트

**2026-11-09 후속:** [DART 테스트 3개 보강·직접 실행·원본 커밋](review-dart-20261109.md)을 추가했습니다. 아래 준비 자료와 당시 기록은 보존합니다.

**2026-11-08 업데이트:** 작성자는 세 항목을 직접 검토했다고 확인했고, 기간 비교 테스트 2개를 저장·실행·커밋했습니다. 최종 전체 143개 통과 출력과 공개 커밋/CI는 [직접 검토 기록](review-20261108.md)에 연결했습니다. 파싱·DART의 별도 개인 실행/수정 증거와 구분합니다.

아래 자료와 [빈 기록지](review-template.md)는 검토 준비 자료입니다. 자료의 초기 `NOT_PERFORMED` 표시는 작성 당시 상태이며, 이후 확인은 위 날짜별 기록을 따릅니다. 과거 AI 실행 기록은 본인 수행으로 바꾸지 않습니다. [실제 학생 피드백](../validation-kit/session-a-20261107.md)은 코드 검토와 별개입니다.

검토 순서는 다음과 같다.

1. [2025 문서 파서 실패와 수정](01-parser-2025.md): 실패 원문·헤더, 명시된 지원 범위, 거부 조건, 파싱과 정본 등록의 차이.
2. [분기/누적·연결/별도 방어](02-comparison-guards.md): 같은 숫자라도 조건이 다르면 성장률을 보류하는 경로.
3. [DART와 IR 단위·문맥 대조](03-dart-ir.md): 백만 원/원 정규화, 단독/누적 필드, 유일한 후보와 출처 확인.

각 자료는 정상 사례와 거부 사례를 실행해 **왜 그 결과가 나왔는지 본인의 말로 설명**하도록 구성했다. 이미 구현돼 있던 방어 로직을 이번에 새로 고쳤다고 쓰지 않는다. 예제의 합성 변형을 실제 공시 오류나 고객 제보로 쓰지 않는다. 2025 원문 행의 수치 불일치 관찰도 사람 검수 결과로 바꾸지 않는다.

명령은 저장소 루트와 설치된 `.venv`를 전제로 한다. 이 키트의 로컬 명령은 유료 API·DART 실호출·재배포 없이 동작한다. `quarterguard.live_verification`의 CLI나 `generate`/`verify_dart`는 호출하지 않는다. 코드 실행이 어렵다면 읽은 부분과 미실행 사유를 그대로 기록한다.

이 키트를 준비하면서 AI가 실행한 로컬 확인: 2026-10-31, `test_core.py` 17개, `test_live_verification.py` 7개, `test_parser_v2.py` 13개 통과. 세 자료의 로컬 예제도 실행해 파서 정상/거부, 정본 ID 기반 비교·보류·누적 차감, DART 대조 정상/합성 거부를 확인했다. 이는 **AI_DEMONSTRATED**이며 작성자 직접 검토나 사용자 테스트가 아니다. 파서의 원문 전체 회귀 검증은 첫 번째 자료의 증거 경로를 따른다. 배포 버전과 현재 작업 디렉터리의 버전은 다를 수 있으므로 본인 검토 시 commit과 diff를 기록한다.
