## 같은 입력을 QoQ와 YoY로 비교한 결과

`load_facts()`의 `s24q3-CFS-revenue-2024-q-KRW`와 `s24q3-CFS-revenue-2023-q-KRW`를 사용한다. 둘 다 3개월임을 `setUp()`에서 먼저 검사한다.

|방식|추가로 검사하는 관계|기대/실제 결과|
|---|---|---|
|QoQ|A 시작 2024-07-01과 B 종료 다음 날 2023-10-01이 인접하는가?|불일치. `['PERIOD_MISMATCH']`, `needs_review`, `None`|
|YoY|종료 연도 1년 차이, 종료 월 일치, 시작 월·일 일치인가?|일치. `[]`, `verified`, `'17.3491'`|

[`compare()`](../../quarterguard/core.py)의 기간 길이 검사만으로는 충분하지 않다는 점을 확인하는 테스트다. `issues`가 있으면 조건식에서 성장률 계산 대신 `None`을 선택한다. 3개월↔6개월 차단에 대한 본인의 설명과 실제 출력도 제공됐지만, 최종 추가 커밋의 두 테스트는 **같은 3개월끼리 날짜 관계가 다른 경우**를 다룬다.

## 세 항목의 검토 근거 수준과 다시 볼 위치

|항목|코드·테스트|현재 본인 확인 근거|

|비교 차단|[`core.py`](../../quarterguard/core.py) `context_issues`, `compare`; [`test_core.py`](../../tests/test_core.py), [`test_my_period_review.py`](../../tests/test_my_period_review.py)|본인의 기간/범위 흐름 검토 확인, 위 실행 출력, 원본 커밋과 CI. 기간 테스트 2개 보강.|
|DART 대조|[`dart.py`](../../quarterguard/dart.py), [`live_verification.py`](../../quarterguard/live_verification.py) `check_dart_rows`; [`test_live_verification.py`](../../tests/test_live_verification.py) `DartCrossCheckTests`|본인이 단위 환산과 중복 거부를 검토했다고 확인. DART 관련 개인 테스트 보강·새 호출 수행 증거는 아직 없음.|

다시 설명할 질문:

1. 파서가 연도를 문서에서 가져오더라도 표 헤더·단위·행·열이 불명확하면 왜 거부해야 하는가? 2025 원문 개선과 fixture 테스트는 무엇이 다른가?
2. 둘 다 3개월인데 QoQ가 막히고 YoY가 통과하는 이유는? 연결/별도가 다르면 어느 검사에서 보류되는가?
3. IR의 백만 원을 DART의 원과 비교할 때 무엇을 곱하는가? 같은 계정 후보가 두 개면 첫 값을 선택하지 않고 거부하는 이유는?

추가 검토는 [빈 기록지](review-template.md)에 본인이 새로 실행한 명령·입출력·설명만 기록한다. 아직 남기지 않은 내용을 대신 작성하지 않는다.
