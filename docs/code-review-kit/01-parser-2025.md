# 1. 2025 원문 파싱 실패와 제한된 레이아웃 수정

**작성자 직접 검토: NOT_PERFORMED.** 실패 분석·수정·아래 자동 재실행은 AI 개발 작업의 근거다. 사용자가 직접 오류를 발견하거나 수정했다고 표현하지 않는다.

## 수정 전 입력과 실제 실패

[보존된 첫 평가](../../data/heldout/first-run.json)의 2025 반기/Q3 연결·별도 표 4개는 모두 `UNSUPPORTED_LAYOUT: header`였다. 이전 `parse_statement`는 `2024 2023`이 네 번 반복된 헤더와 2024년 날짜를 상수로 요구했다. 실제 2025 표의 `2025 2024`가 이 조건에 맞지 않았다. 이는 추측값을 내지 않는 안전한 거부였지만 새 연도 문서를 처리하지 못한 기능 실패다.

추가로 2025 반기 별도 p96에는 숫자가 줄을 넘어 이어지는 형식이 있다. 단순 공백 치환이나 앞자리 주석 개수 고정만으로 처리하면 금액 열이 밀릴 수 있다. 보고서에서 공개된 숫자를 정답에 맞춰 고치는 방식으로 해결하지 않는다.

| 실제 입력 | 공식 원문 / 표 페이지 |
| --- | --- |
| 2025 반기 | [Samsung PDF](https://images.samsung.com/is/content/samsung/assets/global/ir/docs/2025_Half_Interim_Report.pdf), CFS 44 / OFS 96 |
| 2025 Q3 | [Samsung PDF](https://images.samsung.com/is/content/samsung/assets/global/ir/docs/2025_3Q_Interim_Report.pdf), CFS 34 / OFS 89 |

## 수정 후 조건과 읽을 코드

[quarterguard/ingest.py](../../quarterguard/ingest.py)의 다음 함수를 순서대로 읽는다. 자세한 범위는 [파서 v2 설명](../parser-v2.md)에 있다.

1. `_normalize_statement`: 물리적 줄바꿈으로 나뉜 **불완전한 쉼표 그룹**만 세 자리 그룹으로 유일하게 완성될 때 잇는다. 완전한 두 숫자나 일반 공백 사이 숫자는 합치지 않는다.
2. `_statement_context`: 단독 분기→누적 순서, 8개 연도·통화 열, 인접한 현재/전년, 두 기간 종료일, KRW 백만/USD 천 단위, Q2/Q3, 한 개의 연결/별도 헤더, manifest의 날짜·범위·페이지를 대조한다. 회사와 날짜를 문서 ID의 문자열에서 추정하지 않는다.
3. `_row_cells`: 정확히 8개 금액과 선택적인 1~3개 짧은 주석 참조를 검증한다. 행 중복·누락, 불완전한 숫자·열 수·애매한 주석/첫 금액 경계는 거부한다.
4. `parse_statement`: 검증된 문맥으로 `Fact`를 만든다. 기존 호출 형식은 유지한다. 새 회사는 명시적 manifest `company`가 필요하며, 기존 삼성 manifest에는 역사적 기본값이 남아 있다.

금액 추출은 정본 등록과 다르다. 2025 파싱이 성공해도 production의 `data/sources.json`, `data/facts.json`에는 자동 추가되지 않는다. `core.valid_source`가 정본에 없는 2025 fact를 거부하는 것은 별도 단계다.

## 실제 정상 입력과 합성 거부 입력 재실행

아래 명령은 기존 ignored 캐시의 실제 2025 Q3 PDF 해시를 확인하고 CFS p34를 파싱한 뒤, **같은 원문에 잘못된 report_end를 합성 입력**하여 거부를 확인한다. PDF가 없으면 실행 불가로 기록한다. 이 명령은 다운로드·등록·artifact 갱신을 하지 않는다.

```bash
.venv/bin/python - <<'PY'
import hashlib, json
from pathlib import Path
from pypdf import PdfReader
from quarterguard.ingest import parse_statement

docs = json.loads(Path('data/heldout/sources.json').read_text())
doc = next(d for d in docs if d['id'] == 's25q3')
path = Path('work/heldout-raw', doc.get('cache_filename', doc['id'] + '.pdf'))
assert hashlib.sha256(path.read_bytes()).hexdigest() == doc['sha256']
page = doc['statement_pages']['CFS']
text = PdfReader(path).pages[page - 1].extract_text()
facts = parse_statement(text, doc, page)
print('normal', len(facts), facts[0].start, facts[0].end)
try:
    parse_statement(text, doc | {'report_end': '2024-09-30'}, page)
except ValueError as exc:
    print('rejected', str(exc))
else:
    raise AssertionError('conflicting date unexpectedly accepted')
PY
```

2026-10-31 AI 로컬 실행 출력은 `normal 48 2025-07-01 2025-09-30`, `rejected UNSUPPORTED_LAYOUT: reporting date`였다. 위 입력 변경은 거부 경로를 확인하기 위한 합성 반례이며 발행사가 잘못된 날짜를 공시했다는 뜻이 아니다.

## 변경 전후 근거와 한계

[artifacts/parser-development-v2.json](../../artifacts/parser-development-v2.json)에는 수정 전후 파서 해시, 각 PDF 해시, 페이지별 실패와 출력 건수, 보존 데이터의 불변 확인이 있다.

| 데이터 | 변경 전 | 변경 후 | 확인 범위 |
| --- | --- | --- | --- |
| 2024 회귀 | 4/4페이지·192 fact | 4/4페이지·192 fact | 기존 192건의 public record와 완전 일치 |
| 2025 공개 후 개발자료 | 0/4페이지 | 4/4페이지·192 fact | 선언된 64건의 모든 필드 일치. 추가 128건의 독립적인 정답 검수는 아님 |

이 수치는 실제 PDF에서 추출한 출력과 기준값을 비교한 **공개 후 개발 회귀 결과**다. 새 독립 보류 평가나 사람 검수로 표현하지 않는다. 2025 Q3 연결 순이익 행의 기존 수치 불일치는 출력에 그대로 보존했다. 파싱 통과가 그 재무적 불일치를 해결했다는 뜻이 아니다. 미지원 레이아웃·OCR·Q1/연간·새 기업을 일반적으로 처리한다고 주장하지 않는다.

[tests/test_parser_v2.py](../../tests/test_parser_v2.py)의 `ParserV2Tests.test_generic_year_comes_from_verified_header`, `test_only_incomplete_comma_group_can_wrap`, `test_rejects_conflicting_dates_and_quarter`, `test_rejects_ambiguous_or_contradictory_headers`, `test_rejects_duplicate_missing_extra_or_malformed_cells`가 작은 합성 정상·거부 사례다. 전체 원문 4개씩 재현하는 명령은 [파서 문서](../parser-v2.md#local-replay)에 있다.

```bash
.venv/bin/python -m unittest discover -s tests -p test_parser_v2.py -v
```
