# 마지막 보완: 현재 기록 동기화·설명 검사·새 생성 준비

> 2026-11-13 후속: N01–N20의 b 검수(참17·모호3·거짓0)를 수신하고 잔여 보류를 정리해 합의한 보완을 완료했습니다. [최종 기록](https://github.com/sokldjs554/quarterguard/blob/main/docs/final-human-closeout-20261113.md). 아래 생성·준비 단계의 대기 표시는 당시 상태입니다.

범위는 세 가지로 고정한다. ① 완료 기록과 데모·문서 일치, ② 올바른 설명의 과도한 차단 개선, ③ 별도 승인된 새 생성과 같은 참여자 b의 새 응답 검수. 남은 생성 오류는 원응답을 보존하고 제품에서 보류하거나 지원 범위를 제한한다. 무한 재호출이나 추가 필수 참여자 모집으로 확대하지 않는다.

## 1. 현재 기록 동기화

기존 `/api/evaluation/latest`는 `data/latest-progress-v9-20261111.json`을 고정해서 읽고, 화면은 ‘새 b 검수 대기’와 ‘사람 작성 질문 미수신’을 표시했다. 이후 확인된 기록을 반영하지 않은 현재 화면의 오류였다. 해당 과거 JSON은 변경하지 않고 [새 요약](../data/latest-progress-closeout-20261112.json)을 추가했다.

- 본인이 직접 보강·실행한 테스트 6개: 기간 2개, DART 3개, 기간 진단 1개. 본인이 제출한 진단 코드와 테스트의 통합 기록도 유지한다.
- 본인의 당시 전체 Python 239개 실행(1skip)·Node 14개와 AI의 이번 회귀 검사를 구분한다. 과거 143개 실행 기록도 보존한다.
- 본인이 AI 없이 작성한 SK하이닉스 5개·Apple 7개 질문·답안을 반영한다. 이후 구현과 자동 평가에는 AI 도움을 사용했으며, 이미 수정에 사용한 사례는 개발 사례다.
- b의 v9 직접 검수 정정, Apple 7개·SK 4개 실제 사용, A7·S4 다운로드·파일 대조, 이후 질문 변경 시 이전 결과 제거·저장 비활성화 확인을 연결한다. 마지막 상태 확인의 조작자는 별도 미명시이므로 b에게 추가 귀속하지 않는다.
- 외부 고유 참여자는 a·b 두 명이다. b의 개인 자격 금융 실무 경험자 사용은 실제 진행한 일이며, 회사 허가·내부 배포 경험으로 바꾸지 않는다.
- 최신 제품 동일 모델 20건의 개별 사람 판정 합계는 참11·거짓4·모호5다. 제출 말미의 참13·거짓4·모호3 집계도 원기록에 보존한다.
- SK 공개 카탈로그는 연간 비교·연말 잔액 증감·제품 비중 지원을 표시한다. ‘계산 미지원’이라는 초기 추출 단계의 제한은 현재 카탈로그에서 제거하고 원래 추출 manifest는 보존한다. 재고 개월분은 여전히 정의 확인 후 보류한다.

## 2. 과도한 차단 수정

이전 검사는 `required_claim` 전체 문장을 공백 외에는 정확히 복사해야 통과했다. 따라서 금액·날짜·3개월·연결 범위·문서·페이지가 맞아도 괄호·조사·문장 순서가 다르면 차단했다. 또 ‘잘못된 임의 초안 내용은 근거가 없다’는 문장을 실제 검색 근거 부재로 오인했다.

새 검사는 제한된 표현만 추가 지원한다.

- 금액에 바로 붙은 날짜·개월 수·범위를 대조한다. ISO 날짜와 시작 연도가 명시된 한국어 날짜 범위를 지원한다.
- 정확한 등록 문서명·PDF 페이지를 같은 금액 설명 구간에서 확인한다. 근거가 한 문서에만 속할 때는 명시된 공통 문서 위치를 이어받을 수 있으나, 해당 구간에 잘못된 페이지가 직접 적혔으면 거부한다.
- 인용된 ‘임의 초안 내용’에 대한 명시적 부정만 검색 근거 부재 검사에서 구분한다. 뒤에 추가된 실제 근거 부재 주장은 계속 거부한다.
- 금액·날짜·개월 수·연결 범위·페이지 변조, 방향 반전, 도구 실행 이력 오인, 근거 없음의 범위 확대, 연평균 성장률 오명명 방어를 유지한다.

## 3. 새 생성·b 검수 준비 당시 기록

**아래는 승인 전 준비 기록이다.** 이후 [승인된 새20회 생성](closeout-live-results-20261112.md)을 완료했다(추정$0.01895, 제품 검사8/20 통과). 이번 응답의 b 검수만 실제 결과를 기다린다. 준비 당시 새 호출0회·새 검수0건이었다. 이전 b의 판정을 새 응답에 복사하지 않는다.

- 모델: `gpt-4.1-mini-2025-04-14` (공개 제품 경로와 동일).
- 대상: 직전 20개 설명 사례의 동일한 저장 도구 결과. 이번에는 실제 MCP 재실행·새 PDF 파싱·도구 계획 호출을 하지 않는다.
- 최대20회, 재시도0회. 회당 입력 사전 상한16,000토큰, 출력 상한700토큰. 입력은 전체 직렬화 요청의 UTF-8 바이트 수+1,024 여유분으로 보수적으로 제한하며 API의 입력 토큰 제한 옵션은 아니다.
- 공식 단가 입력$0.40/백만·출력$1.60/백만 기준 최대 추정$0.15040, 승인 예산$0.16(세금·환율 제외), 청구액 미조회.
- 모델은 공식 문서에 deprecated로 표시된다. 사용 불가 시 다른 모델로 바꾸거나 재시도하지 않고 실패를 기록한다.
- 기존 Actions `OPENAI_API_KEY`를 재사용하되 새 배치 승인을 별도로 받는다. 이전 승인 잔여량을 사용하지 않는다.
- 고정 요청·코드 해시 확인, main의 전용 workflow, 한 번의 dispatch, 재실행 차단, 고정 계약별 사용 기록으로 범위를 제한한다. 승인 전 준비는 네트워크 호출을 하지 않는다.
- 생성 원문·자동 거부도 모두 보존하고 빈 사람 검수 양식을 만든다. b는 새 응답의 설명·구조 필드·근거 ID·본문 출처를 판정한다. 참여 기록은 사용자가 전달한 실제 결과로만 채운다.

준비 코드: [closeout_evaluation.py](../quarterguard/closeout_evaluation.py), [전용 workflow](../.github/workflows/closeout-explanations.yml). 생성·검수 이후에도 오류가 남으면 해당 설명을 보류하고 범위를 명시한 뒤 이번 보완을 종료한다.
