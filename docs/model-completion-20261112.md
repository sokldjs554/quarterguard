# 모델 실행·설명 보완 — 코드와 무료 검증, 실호출 대기

**후속 상태:** 아래는 실행 전 준비 기록이다. 승인 후 [새 실제 실행 결과](model-completion-live-results-20261112.md)가 추가됐다. 36회 호출, 모델 도구 선택4/4 일치, 구조·근거ID20/20 일치, 실행 당시 제품 검사4/20 통과다. 새로운 사람 판정은 아직 없으며 원기록은 보존한다.

금융 업무 경험자 b의 실제 사용·직접 검수는 이미 확보했다. ‘실제 운영 경험 없음’으로 묶지 않는다. 남은 이번 작업은 모델이 근거 조회 누락에서 복구하는지, 새 원응답이 금액·문맥·출처를 정확하게 설명하는지를 다시 확인하는 것이다.

## 보존한 실패와 변경

- [이전 실제 모델/MCP 실행](../artifacts/final-live-20261111/run/report.json): 4과제 중 3개 결과 일치. 연결·별도 과제는 모델이 근거 읽기를 생략해 `UNREAD_FACT`로 미완료. 차단은 올바르지만 과제 완료로 세지 않았다.
- [제품 모델 P01~P04 사람 검수](validation-kit/final-followup-20261112/README.md): 설명 참2·거짓2, 구조 일치3/4. 큰 수 한글 단위와 백만 원을 섞은 금액 오류 및 `issues` 코드 번역 오류를 보존한다.
- [v9 사람 검수 정정 기록](validation-kit/final-followup-20261112/v9-human-review-correction.json): 참13·모호3. AI 판정이라는 초기 표기는 사용자 확인으로 정정됐으며 b의 직접 검수다.

`bounded_planner.run()`은 두 검색이 끝나고 A/B 방향·모드가 허용된 비교에서만 근거 읽기 누락을 복구 대상으로 삼는다. 계산 도구는 호출하지 않고 누락 ID를 다음 모델 입력에 전달한다. 모델이 직접 `get_fact`를 선택한 뒤 비교를 다시 요청해야 한다. 누락을 코드가 자동 조회해 모델 성공으로 세지 않는다. 과제당 모델 결정 최대8회, 복구 안내 최대2회이며 다른 잘못된 입력·위조 응답·반복 성공 도구·시간 초과는 계속 종료한다. 차단된 시도와 실제 MCP 호출을 trace의 `executed`로 구분한다.

`build_payload()`는 status·issues의 원래 코드와 개수도 생성 스키마로 제한한다. 근거별 금액·표시 단위·날짜·개월 수·연결 범위·문서·쪽수를 묶은 `required_claim`을 원응답에 포함하도록 요청한다. 기간 보류의 설명은 도구 보고와 별도 재계산을 구분한 문장을 요구한다. `check_grounding()`은 누락·다른 금액·다른 증감률·지원하지 않는 큰 수 단위 표현을 거부한다. 원응답을 사후 수정하거나 정해진 문장으로 대체하지 않는다.

자유 문장 전체의 의미를 인증한 것은 아니다. 특히 필수 문장 뒤에 덧붙인 비수치 문장의 모순, 지원하지 않는 표현의 의미는 사람 검토가 필요하다. 새 생성에서 형식 요구가 누락되면 올바른 문장도 차단될 수 있다. 이런 결과도 성공으로 바꾸지 않는다. 생성 제약과 후속 차단을 함께 평가하며 ‘프롬프트만으로 정확도 개선’이라고 주장하지 않는다.

## 무료 검증과 재현

```bash
python -m unittest tests.test_bounded_planner tests.test_planner_recovery tests.test_generation_grounding tests.test_completion_evaluation
python -m unittest discover -s tests
node --test tests/*.mjs
python scripts/check_artifacts.py
python -m quarterguard.completion_evaluation --dry-run --output work/completion-new-dry-run
```

출력 폴더는 기존 경로를 덮어쓸 수 없다. [첫 무료 실행](../artifacts/model-completion-20261112/dry-run/report.json)에서는 실제 MCP 서버의 네 과제가 모두 기준 결과와 일치했다. 연결·별도 과제의 조회 누락을 테스트 정책으로 주입해 결정6회·실제 도구5회·복구1회를 확인했다. 다른 세 과제는 정상5회, 기간 보류5회, 근거 없음1회였다. **정책은 스크립트이고 LLM 호출은0회**다. 모델 성공률4/4로 표현하지 않는다.

[최종 무료 실행](../artifacts/model-completion-20261112/final-dry-run/report.json)과 [전체 검증 로그](../artifacts/model-completion-20261112/)를 함께 보존한다. 중간 전체 회귀 실패도 지우지 않는다. 강화된 설명 요구로 기존 합성 성공 응답과 좁은 구형 단위 테스트가 실패했고, 프롬프트가 과거 배치의 입력 상한을 넘었다. 입력 상한을 늘리지 않고 중복 지침을 줄였으며, 합성 성공 응답은 새 요구에 맞추고 과거 원응답·판정은 수정하지 않았다.

## 준비된 새 실호출 계약 — 아직 미실행

- 모델: 제품과 같은 `gpt-4.1-mini-2025-04-14`.
- 대상: 설명20건(실제 MCP 결과4 + 기존 v9 도구 결과 재생16), 모델 선택/MCP4과제.
- 최대52회: 설명20회 + 과제당8회×4. HTTP 재시도0. 복구 단계도 이 상한 안에 포함.
- 회당 입력 사전 상한16,000: 전체 요청 UTF-8 바이트+프레이밍 여유1,024로 보수적 제한. API 자체 입력 토큰 제한 옵션이라는 뜻은 아니다. 출력 최대700토큰.
- 공식 단가 입력$0.40/백만, 출력$1.60/백만 기준 최대 추정$0.39104, 승인 예산$0.40(세금·환율 제외). 청구액 미조회. [모델/단가](https://developers.openai.com/api/docs/models/gpt-4.1-mini), 확인일2026-11-12.
- 공식 페이지는 이 모델을 deprecated로 표시한다. 이전 제품 배치와 같은 모델을 비교하기 위한 선택이며, 호출 불가 시 중단하고 다른 모델로 자동 대체하지 않는다.
- 새 계약·새 워크플로·입력/코드 해시를 [freeze](../data/completion-evaluation-freeze.json)에 고정. 이전 승인·예약 기록 재사용 금지. 기존 Actions 키 사용도 이 새 범위의 승인 후에만 실행.
- 요청 전에 호출을 예약하고 실패도 원응답/사용량과 함께 기록. HTTP/API 전송 실패 후 추가 유료 요청 중단. 계획 제한90초 후 새 결정은 종료하며, 이미 시작한 HTTP 호출의 사용량 기록을 위해 최대30초의 정리를 허용한다.

20건 모두 수정에 사용한 개발 사례다. 새 독립 평가셋이 아니다. 재생16은 이전 GPT-5.4 mini에서 제품 GPT-4.1 mini로 모델도 달라지므로 프롬프트만의 효과를 분리할 수 없다. 실제 MCP4와 재생16은 보고서에서 분리한다. 이 실행에서 원문 PDF를 새로 파싱하지 않는다.

완료 판정은 새 실호출의 모델 과제4개 기준 일치, 설명20건 구조·근거 검사 결과, 새 원응답에 대한 사람 의미 판정을 따로 기록한 뒤 내린다. 한 건이라도 실패하면 실패를 공개하고 해당 범위를 부분 완료로 남긴다. `human-review.json`에는 차단된 응답도 포함하고 사람 이름·판정은 빈칸으로 둔다. 기존 b의 검수 결과를 새 응답에 옮기지 않는다.

## 실제 사용자 경험과 일반화

- 완료된 근거: 학생 a와 금융 업무3년 경력 지인 b의 실제 사용·후속 의견. b의 Apple/SK 화면 조작, 다운로드 JSON 대조, 실제 LLM 응답20건 직접 검수. 사용자의 코드 검토·테스트 제출과 AI 없이 작성한 질문도 별도 증거다.
- 금융 실무자 개인의 공개 데모 사용은 실제 사용자 검증이다. 회사 내부망·비공개 데이터·조직 승인 배포와 다르지만, 그래서 실사용 경험이 없어지는 것은 아니다.
- 남은 한계: 회사 환경 배포·장기 다사용자 운영·독립 신규 문서 전반의 성능은 아직 입증하지 않았다. 참여자 수는 반복 세션을 합쳐 고유2명으로 유지한다. 이번 코드 수정을 b가 사용했다고 새 기록을 만들지 않는다.

## 추가 검사 범위와 리뷰

과거 실제 응답20건을 새 검사에 그대로 넣으면 필수 근거 문장의 새 형식을 충족하지 못해20건 모두 차단된다([그대로 재생한 결과](../artifacts/model-completion-20261112/historical-replay.json)). 이것은 과거 사람 판정을 거짓20건으로 바꾸는 결과가 아니다. 새 형식의 차단률과 설명 의미의 정확도는 다른 지표다. 새 생성에서 요구한 형식까지 지키는지는 아직 확인하지 않았다.

독립 AI 코드 리뷰에서 `999조원`처럼 붙여 쓴 단위가 검사에서 빠지는 문제1건을 발견했다. 띄어쓰기 없는 표현도 차단하도록 수정하고 회귀 테스트를 추가했다. 사람 b의 발견이나 검수로 기록하지 않는다. 수정 후 [실제 MCP 무료 재실행](../artifacts/model-completion-20261112/reviewed-dry-run/report.json)과 [리뷰 후 전체 테스트](../artifacts/model-completion-20261112/python-tests-reviewed.txt)를 최종 코드의 검증으로 사용한다. 이전 실행·입력 freeze도 보존한다.
