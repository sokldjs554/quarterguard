# 저장 JSON 파일 재열기 보완

사용자가 전달한 b의 결과: **“파일 내용은 열어보지 못했습니다. 브라우저 보안 정책이 내려받은 파일의 file:// 열기를 차단해 화면과 파일 내용의 일치 여부는 미확인입니다.”** 이 미확인은 그대로 보존한다. b의 환경에서 발생한 정책 오류를 AI가 직접 재현했다고 주장하지 않는다.

## 구현 범위

기존 공개 자료 검토·저장 흐름에서 파일 내용을 확인할 수 있게 하는 작은 보완이다. 대안은 OS 텍스트 편집기에서 열기, 웹앱 내 현재 결과만 미리보기, 사용자가 고른 저장 JSON을 웹앱에서 읽기다. AI가 세 번째 방법을 선택했다. 별도 편집기 설치를 전제하지 않고 실제 내려받은 파일을 읽을 수 있기 때문이다. 현재 결과만 미리 보는 방식은 저장 파일을 확인했다는 근거가 되지 않는다.

근거 검색 화면에 ‘저장한 JSON 파일 확인’을 추가한다. 파일 선택 권한은 표준 브라우저 파일 선택창에서 사용자가 부여한다. file:// 접근 제한이나 보안 설정을 해제하지 않는다. File API로 브라우저 안에서만 읽고 서버 업로드·외부 API 호출·영속 저장을 하지 않는다.

파일명, 질문 또는 계산 방식, 입력·기간·통화·배율·출처·판정·보류 이유와 전체 JSON을 표시한다. 파일의 문자열은 텍스트로만 표시하며 HTML이나 링크로 실행하지 않는다. 현재 검토 결과가 있으면 JSON 값과 필드를 대조한다(공백·객체 키 순서는 제외, 배열 순서 유지). 일치는 현재 결과와의 값 대조이며 원문 정확성이나 파일 출처의 진위 확인이 아니다.

잘못된 JSON·미지원 형태·1MiB 초과·과도한 중첩·읽기 실패는 확인 불가로 표시한다. 다른 파일 선택, 질문·입력·문서 변경, API 실패, 늦은 파일 읽기 완료 후에도 이전 일치 표시가 새 결과처럼 남지 않게 한다. 기존 다운로드와 계산 판정은 유지한다.

## 검증 계획

1. 기존 화면에 파일 재열기 수단이 없는 것을 브라우저 검사로 확인한다.
2. 실제 다운로드 파일의 값 대조, 다른 입력·변조 파일·잘못된 파일·내용 실행 방지와 읽기 중 조건 변경을 검사한다.
3. PC·모바일 크기에서 A7/S4의 다운로드 → 파일 선택 → 내용 확인과 불일치·오류 복구를 실행한다. 로컬 파일 선택이 네트워크 업로드를 만들지 않는지 검사한다.
4. 기존 회귀, CI, 배포와 공개 서버 검사를 마친다. 새 b 수행 기록으로 세지 않는다.

## b가 다시 확인할 순서

1. [데모](https://quarterguard.onrender.com/)를 새로고침하고 **근거 검색**에서 A7 또는 S4를 실행한다.
2. 기존 **JSON 저장** 버튼으로 파일을 내려받는다.
3. 같은 화면 아래의 **저장한 JSON 파일 확인**을 펼친다.
4. **내려받은 JSON 파일 선택**을 눌러 다운로드 폴더의 파일을 고른다. 브라우저 주소창에 file://를 넣지 않는다.
5. 파일명과 일치/불일치 안내, 질문 또는 A/B 입력, 원문 위치, 보류 이유를 읽는다. **선택한 파일 전체 내용**을 펼치면 읽어온 원문 JSON도 볼 수 있다.

기존 파일도 열 수 있다. 현재 결과를 실행하지 않았다면 ‘파일 내용만 읽음’으로 표시된다. 다른 질문·조건의 파일이면 ‘내용이 다름’으로 표시한다. 다른 과제와 LLM20건을 다시 검수할 필요는 없다. 실제 기기에서 수행한 성공·실패와 읽은 값만 후속 기록으로 남긴다.

## 구현과 자동 검사

- [파일 읽기·비교 모듈](../web/json-file-review.js): 선택 파일을 File API로 읽고 구조를 검사한다. 원문 문자열과 요약은 textContent로 표시한다. 파일 안의 HTML·주소를 실행하지 않는다.
- [단위 검사8개](../tests/test_json_file_review.mjs): 실제 과거 다운로드 fixture의 필드·값 유지, 공백/키 순서, 다른 질문/수치/추가·누락 필드, 미비교 상태, 잘못된 JSON·크기·중첩·숫자, 문자열 보존을 검사한다. 이 단위 검사는 원문 재파싱 또는 새 문서 평가가 아니다.
- [브라우저 검사](../scripts/browser_json_file_review.py): 로컬 실제 서버에서 새 다운로드를 만들고 파일 선택으로 읽는다. 읽기 시 네트워크 요청0건을 확인한다. 다른 파일·잘못된 JSON·큰 파일, HTML 문자열, 읽기 실패·늦은 완료, 질문·문서·계산 조건 변경 후 상태를 확인한다.
- 읽기 실패·늦은 완료·취소 이벤트는 명시적 주입이다. b에게 발생한 실제 실패나 고객 사용 건수로 세지 않는다.
- 파일 읽기 최초 브라우저 검사는 테스트의 실패 주입 함수를 Playwright가 즉시 실행하는 테스트 코드 오류로 중단됐다. [실패 로그](../artifacts/json-file-review-20261112/local.log)를 보존하고 주입 함수를 수정했다. 제품의 실사용 실패로 집계하지 않는다.
- 초기 구현에서 파일을 읽은 뒤 선택창의 파일명이 비워지는 문제를 [실패 검사](../artifacts/json-file-review-20261112/selected-name-red.log)로 확인하고, 읽은 파일명이 유지되도록 수정했다.

[최종 로컬 브라우저 결과](../artifacts/json-file-review-20261112/local-final/report.json): 1365×900 및 390×844 통과. [기존 다운로드 회귀](../artifacts/json-file-review-20261112/export-regression/report.json)도 두 크기 통과. 모바일 크기 Chromium이며 실제 안드로이드 사용자 검사가 아니다.
