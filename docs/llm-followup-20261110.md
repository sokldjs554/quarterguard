## 비교 설계와 해석

이전의 [실제8개 응답](../artifacts/llm-live-20261109/report.json)과 같은8개 개발 사례를 사용한다. 입력의 도구 결과는 당시 실제 MCP 결과를 **재생**한 것이며 이번 단계의 새 MCP/PDF 실행이 아니다. 새 생성 요청에 지침과 도구 근거 안내를 함께 추가하므로 두 변경의 효과를 따로 분리할 수 없다. 개선에 사용한 사례이며 별도 보류셋이나 무작위 표본이 아니다.

기존 `explanation_audit`의 금융 수치·문맥·인용 검사기를 그대로 적용한다. 별도로 표시 단위 문구, 문서명/페이지 문구, 검색 범위 한정, 내부 `scale` 용어 여부를 이전·이후 모두 같은 함수로 검사한다. 이것은 **문자열 포함 검사**여서 올바른 다른 표현을 놓치거나 의미 오류가 있는 문장도 포함 검사에 통과할 수 있다. 자동 통과를 금융 정확성이나 사람의 참 판정으로 바꾸지 않는다. LLM-as-judge는 사용하지 않는다.

공개 생성 경로의 실제 모델은 여전히 GPT-4.1 mini다. 이번에는 기존 GPT-5.4 mini 평가와 모델을 맞춰 비교한다. 이를 공개 데모 모델의 개선 성능으로 주장하지 않는다. 기존 모델 출력·사람 판정(참5·모호3)·동결 입력·실패 기록을 덮어쓰지 않는다.

## 실행 통제

[새 하네스](../quarterguard/evaluate_live_explanations_v4.py), [동결 파일](../data/llm-followup-20261110/freeze.json), [수동 워크플로](../.github/workflows/live-explanations-v4.yml). 키는 기존 Actions 비밀값에서만 제공하며 내용은 조회·출력하지 않는다. 워크플로는 재실행과 이전 dispatch 존재를 검사하고 키 노출 전에 동결을 검증한다. 실제 API 시도는 네트워크 요청 전 원장에 기록하며, 이미 원장이 있으면 실행하지 않는다. 출력과 실패도 별도 artifact로 보존한다.

이 문서는 **준비 및 승인 시점 기록**이다. 실호출 횟수·사용량·비용·이전/이후 검사 결과는 실행 후 별도 결과 문서에서 확인해야 한다. 여기의 최대8회는 아직 실행 결과가 아니다.
