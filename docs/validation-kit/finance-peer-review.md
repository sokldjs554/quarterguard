**후속 업데이트:** [세션 b](session-b-20261108.md)의 문서·코드 검토 의견과 익명 요약 최종 공개 동의를 확보했습니다. 아래 준비 상태와 빈 기록지는 최초 작성 당시 자료로 보존하며, 참여자의 직접 조작 결과는 별도로 수집합니다.

## 전달할 문안

> 내가 만든 QuarterGuard에서 공개 공시의 출처와 비교 조건을 확인하는 흐름을 20~30분 봐줄 수 있을까? 삼성전자 공개 IR 자료만 쓰고, 회사 내부 자료나 고객 정보는 필요 없어. 가능하면 네가 직접 원문을 열고 정상 비교와 계산 보류를 확인해 주면 좋겠어. 어떤 업무 경험을 바탕으로 의견을 주는지도 공개 가능한 범위에서 알려줘. 참여와 익명 의견의 지원서·GitHub 공개는 따로 동의를 받고, 공개할 요약은 먼저 보여줄게. 참여를 중단하거나 공개를 거절해도 괜찮아.

## 시작 전에 확인할 질문

1. 현재 역할과 관련 업무는 무엇인가? 공시/재무제표/금융 데이터 분석 경험은 어느 정도인가? 회사명·실명은 불필요하며 공개 가능한 직무와 경력 범위만 받는다.
2. 개인 자격의 검토인가, 회사가 허락한 업무 검증인가? 친구 관계는 그대로 기록한다. 회사가 허락하지 않았다면 회사의 검증으로 표시하지 않는다.
3. 참여, 관찰 메모 보관, 익명 요약의 지원서 활용, 공개 GitHub 게시, 화면 캡처 각각에 동의하는가? 공개 전 요약 재확인 방식과 삭제 요청 방법·보관 기한은?
4. 직접 조작할 수 있는 기기·브라우저와 일정은? 직접 조작이 어렵다면 개발자 시연에 대한 의견 수집으로 기록한다.

## 실제 고객 환경으로 이어질 경우

친구의 회사 재직 사실만으로 회사 접근·배포 허가가 생기지 않는다. 기관이 검증을 허용하면 권한 있는 담당자의 승인 범위, 접근 계정·기한, 사용 자료와 공개 가능 여부, 배포 장소/방식·비용·운영 담당자, 외부 API/데이터 반출 허용 범위, 테스트와 성공 기준, 중단·삭제·복구 방법을 먼저 문서화한다. 승인 전에는 공개 데모와 공개 문서만 사용한다. 현재 고객사 인프라에 배포·사용한 사실은 없다.
