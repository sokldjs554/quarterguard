# b에게 전달할 v7 재검수 안내 — 아직 새 응답 없음

이 문서는 수행 안내이며 참여 기록이 아니다. 승인 후 실제 생성된16개 응답을 원문 그대로, 도구 결과와 발행사 PDF의 문서·페이지·행·열 링크와 함께 제공한다. 지금은 새 응답이나 판정을 작성하지 않는다.

진행자가 b에게 전달할 문안:

> 지난번 확인해 준 JSON 값의 % 혼입, 부정문 차단, QoQ 보류 이유를 보완한 뒤 새로 생성한 응답을 확인해 줄 수 있을까? 새 문장을 먼저 원문·도구 결과와 대조하고, 그다음 이전 문장과 비교해 줘. 같은16개 사례라 이미 본 내용이지만 이전 판정을 그대로 복사하지 말고 실제 확인한 사례만 남겨 줘. 설명과 구조 필드, 근거 ID를 따로 판정해 줘.

|---|---|---|---|---|---|---|
|직접 확인한 사례만 작성|||||||

1. JSON `value`는 도구의 문자열 또는null 그대로인가? 본문의 증가율에는 `%`가 있지만 JSON 값에는 없는지 확인한다.
2. 금액·단위·기간·연결/별도·회사·문서·페이지가 근거와 같은가? 근거 ID 철자와 문장 속 출처 지칭을 각각 본다.
3. 근거가 있지만 비교를 보류하는 상황을 검색 실패라고 설명하지 않는가? 부정문은 문장 전체 의미로 판단한다.
4. `s22-op-qoq`는 둘 다3개월이며 직전 분기가 아닌 날짜 관계가 문제다. 이를 기간 길이 문제와 혼동하지 않는가?
5. 새로운 오류와 모호함도 기록한다. 자동 통과 여부와 관계없이 판단하며, 못 본 원문·사례는 미확인으로 남긴다.

실제 수행자, 검토 날짜·시각·시간대, 기기·OS·브라우저, 받은 도움, 확인한 자료 범위를 함께 적는다. 새 기록의 익명 GitHub·지원서 활용 문안을 b에게 보여 주고 공개 범위를 확인한다. 기존 동의를 새 결과의 공개 확인으로 대신하지 않는다. 회사 자료·비공개 정보는 사용하지 않는다.
