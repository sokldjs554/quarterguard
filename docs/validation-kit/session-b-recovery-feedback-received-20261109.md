# b의 표 위 설정 이동 버튼 후속 의견 — 2026-11-09 접수

진행자는 아래 의견도 **b가 직접 확인했고 익명 GitHub·지원서 공개 확인을 완료했다**고 답했다. 기존 참여자 b 한 명의 추가 의견이며 새 참가자로 집계하지 않는다. b의 직무·경력·친구 관계는 [기존 기록](session-b-20261108.md)의 진행자 제공 정보다. 회사 승인·금융기관 고객 환경 검증을 의미하지 않는다.

대상은 [비교표 위 기간·범위 설정 이동 버튼](../recovery-shortcuts-20261109.md)이 추가된 화면이다. 아래 의견은 **설정 닫고 결과 보기 버튼을 추가하기 전**에 받은 것으로, [새 결과 복귀 기능](../settings-return-20261109.md)의 사용 결과가 아니다. 실제 수행 날짜·시각·소요시간·배포 SHA·화면 크기·세부 기기 버전은 이번 제출에 없었다. 접수일을 수행일로 바꾸거나 이전 세션의 시간·환경을 재사용하지 않는다.

## 전달받은 의견

다음은 진행자가 전달한 문장을 Markdown 형식만 정리해 옮긴 것이다. 독립적으로 확보한 녹취나 AI가 생성한 참가자 답변이 아니다.

> **설정에서 결과로 돌아오는 동작은 남아 있습니다.** 기간을 바꾼 뒤에도 설정 영역이 열린 상태로 유지됩니다. 확인한 화면 높이에서는 금액과 증감률 전체를 다시 읽으려면 설정을 닫거나 조금 내려야 했습니다. B 기간 선택칸으로 이동한 위치에서는 ‘닫기’ 버튼이 화면 위쪽 밖에 있었습니다.

> **버튼 문구가 조금 간접적입니다.** `B 기간 설정 확인 →`으로도 이동할 곳은 알 수 있지만, **`B 기간 수정 →`**이라고 쓰면 바꿀 수 있다는 점이 더 분명하겠습니다.

> **보류 상태에서는 상단 안내만큼 세로 공간이 늘어납니다.** 첫 매출 행이 아래로 밀리지만, 정상 비교로 복구하면 안내가 사라집니다. 각 금액 아래 설명 때문에 표 자체가 길어진 점은 그대로입니다.

> 이번 변경으로 **“보류 원인은 알겠는데 수정하러 어디로 가야 하지?”라는 불편은 줄었습니다.** 다음으로 하나만 다듬는다면, 기간을 바꾼 뒤 **설정을 닫고 비교 결과로 돌아가는 동작**을 가까이 두는 쪽이 도움이 되겠습니다.

## 해석과 다음 변경

참여자는 수정하러 갈 위치를 찾는 불편이 줄었다는 정성 의견과 남은 불편 세 가지를 전달했다. 이를 작업시간 단축률, 모든 업무의 성공률, 전 화면의 사용성 개선으로 확대하지 않는다. 이번 제출에는 새 금액 검산·원문 대조·DART 조회·CSV 재검사 결과가 없었다.

다음으로 결과 복귀 동작 하나를 구현·자동 검사했다. 문구 변경과 정보량 조정은 그대로 남았다. 새 복귀 버튼에 대한 사람의 사용 결과는 아직 없다. 과거 사용자 기록과 자동 검사를 새 사람 검증으로 바꾸어 표현하지 않는다.

익명 공개 요약은 계속 보관할 수 있다는 기존 동의 구분을 유지한다. 원본 메모·캡처는 참여 종료일부터 30일 보관 대상이나 이번 실제 수행일이 미제공되어 새 원본 만료일은 임의로 정하지 않았다. 삭제 요청은 기존 연락 수단으로 진행자에게 전달한다.
