# 최신 기능·LLM 최종 확인 묶음 — 실제 참여 대기

[공개 데모](https://quarterguard.onrender.com/) · [배포 기준·기능 결과](../../apple-product-support-20261112.md)

이 자료는 AI가 준비한 **진행 안내와 빈 기록지**입니다. 실제 사용·검수를 수행한 기록이 아닙니다. 기존 본인 작성 Apple7질문과 최초/수정 후 평가는 이미 있으므로 새 질문을 다시 작성할 필요는 없습니다. 기존 학생 참여자a와 금융 업무 경험자b는 각각 같은 한 명으로 집계하며, 본인 사용은 작성자 자기 검증으로 구분합니다.

## 진행 순서

1. **최신 기능 사용:** [업무 카드](live-tasks.md)를 보고 실제 데모를 조작합니다. Apple7개 + 아직 후속 사용 기록이 없는 SK4개입니다. [빈 사용 기록 CSV](live-use.csv)에 직접 읽은 값·판단·막힌 점을 적습니다.
2. **실제 LLM20건 검수:** [원응답·도구 결과·원문 링크](llm-20.md)를 읽고 [빈 판정 CSV](llm-review.csv)를 작성합니다. P01~P04(제품 동일 모델4건)를 먼저, V01~V16(v9별도16건)을 이어서 해도 됩니다. 날짜가 다르면 나누어 기록하세요.
3. **돌려줄 것:** 작성한 표 또는 CSV, 실제 검토 날짜·시간대·환경·받은 도움, 직접 확인하지 못한 범위. 캡처/저장 JSON은 가능한 경우에만 함께 전달합니다. 확인하지 못한 칸은 미확인으로 남깁니다.

이 묶음의 LLM 문장은 이미 생성된 원응답입니다. 새 호출0회, 새 비용0달러이며 이번 작업은 새 프롬프트의 생성 실험이 아닙니다. Apple 새 기능의 설명은 규칙 기반으로 작성되므로 LLM20건에 넣지 않습니다.

## b에게 전달할 메시지

> QuarterGuard 마지막 확인을 부탁해. 이번에는 실제 데모의 Apple 새 기능과 SK 계산을 조작해 보고, 아래 업무 카드에 직접 읽은 값·보류 이유·막힌 부분을 적어 줘. 이어서 실제 모델 응답20건을 원문/도구 결과와 대조해 문장 판정, 구조 필드, 근거 ID를 각각 확인해 주면 돼. 4건과16건은 다른 모델·배치라 이전 판정을 옮겨 적지 말아 줘. 모르는 부분은 미확인으로 남겨도 되고, 날짜·환경·받은 도움도 실제대로 적어 줘. 나누어 진행해도 괜찮아.
>
> 데모: https://quarterguard.onrender.com/
>
> 안내: https://github.com/sokldjs554/quarterguard/blob/main/docs/validation-kit/final-handoff-20261112/README.md

이 메시지를 AI가 b에게 직접 보내지는 않았습니다. 진행자가 기존 연락 수단으로 전달합니다. 기존 b의 후속 검수·공개 동의 범위는 유지하고 동일 동의를 다시 묻지 않습니다. 새로운 사람/새 비공개 자료/공개 범위 변경이 생기면 그 부분만 실제로 확인합니다. 금융회사 업무 경험자가 개인적으로 참여해도 회사 승인·고객 환경 배포로 기록하지 않습니다.

## 기록 원칙

- 본인이 직접 했으면 `작성자 본인`, b가 했으면 `b`. 본인 확인과 외부 사용자를 합치지 않습니다.
- 날짜·환경·받은 도움은 이번 실제 수행 값을 적습니다. 이전 안드로이드/Chrome·도움 없음 기록을 자동 복사하지 않습니다.
- 회사의 비공개 자료는 필요 없습니다. 제공한 공식 공개 공시만 사용합니다.
- 자동 검사는 사람 판정과 별개입니다. 판단 후에만 [참고 자료](reference-after-review.md)를 열어 대조합니다. 미리 읽었다면 사전 열람으로 적습니다.
- 기존 실패/검수 원본을 변경하지 않고, 새 수행 기록과 새 판정은 후속 파일로 추가할 예정입니다. 아직 빈 표를 성공 건수로 집계하지 않습니다.
- [기계 확인용 원응답 묶음](llm-20-source.json)과 [원문 텍스트 해시](manifest.json)를 함께 제공합니다. 20문장의 내용은 저장된 모델 응답과 정확히 일치합니다.
