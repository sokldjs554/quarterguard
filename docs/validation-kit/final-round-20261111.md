# 최종 사람 검수 묶음 — 미수행 양식

기존 b의 참여·공개 동의를 다시 요청하는 문서가 아닙니다. 새로 실제 확인한 결과만 기입합니다. 동일 b는 계속 한 명으로 계산합니다. 이번 양식은 AI가 준비했으며 아직 참여 결과가 없습니다.

## A. 최신 v9 실제 설명

[실제 응답16건](llm-prose-v9-actual-20261111.md)과 [빈 판정표](llm-prose-v9-review-20261111.md)를 사용합니다. 이전 v8 판정을 복사하지 않습니다. 구조 검사16/16과 설명 의미 판정은 별개입니다.

별도 자동 감사는16건 중15건에 경고를 냈습니다. [사례별 경고](../../artifacts/final-hardening-20261111/v9-audit-triage.json)를 보고, 참인 문장의 과잉 탐지인지 실제 잘못된 수치·기간·인용인지 구분해 주세요. 경고를 없애기 위해 판정을 바꾸지 않습니다.

기록: 사례 ID / 설명 참·거짓·모호 / 근거 ID 일치 여부 / 경고가 타당한지 / 확인한 원문 / 이유.

## B. 새 SK하이닉스 기능 직접 사용

[데모](https://quarterguard.onrender.com/) → 근거 검색 → SK하이닉스 → 선택 근거로 계산.
[업무별 상세 양식](source-calculation-followup.md)을 사용합니다.

1. 현금의2024말·2023말 기준일을 읽고 차이와 증가율을 원문과 대조.
2. DRAM / 같은 연도 제품 합계 비중을 확인하고 B를 다른 연도로 바꾸어 보류 확인.
3. 영업손익 비교에서 흑자 전환·금액 차이는 표시되지만 음수 기준 증감률은 보류되는지 확인.
4. 재고 개월분에서 추가로 정해야 하는 조건을 본인 말로 설명.
5. JSON 저장 후 문서·PDF쪽·인쇄쪽·행·열·계산 조건을 다시 찾기.
6. 조건 변경 뒤 이전 결과·저장 기능이 그대로 남지 않는지 확인.

각 업무: 실제 읽은 값 / 수행·보류·실패 / 막힌 점 / 받은 도움. 날짜·환경은 실제로 확인한 범위만 기록합니다. 안드로이드 기종·브라우저 버전을 모르면 미수집으로 남깁니다. 이번 내용을 회사 공식 승인이나 고객 환경 배포로 기록하지 않습니다.

## C. 새 사람 작성 질의

질문과 정답을 AI가 대신 만들지 않습니다. 기존5질문 및 이미 공개된 평가 질문과 다른6~8개를 직접 작성합니다. 다른 기간·다른 문서가 좋으며, 지원 범위를 벗어나는 것도 실패/보류 평가로 남깁니다.

|ID|직접 작성한 질문|선택한 문서(없으면 없음)|원문 URL·PDF쪽/인쇄쪽·표·행·열|직접 읽은 금액·단위·기간·범위|답변 가능/조건 확인/미지원|이유|
|---|---|---|---|---|---|---|
| | | | | | | |

작성자(본인/b/다른 사람), AI 사용 여부를 함께 기록합니다. 작성 완료 후 원본을 고정하고 첫 실행 전에 코드·데이터 해시를 기록합니다. 정답을 검색 입력에 보태거나, 실패 결과를 지우고 수정 후 결과를 첫 결과로 쓰지 않습니다.

개발자는 아래 CLI로 표를 JSON으로 충실히 전사합니다. 질문/정답 의미를 AI가 바꾸지 않습니다. `expected.rows`에는 사람이 확인한 원문 속성을 넣습니다. 실행기는 question/document_id만 검색에 전달하며 정답은 점수 계산에만 씁니다.

```bash
python -m quarterguard.human_holdout freeze work/human-cases.json work/human-frozen.json
python -m quarterguard.human_holdout run work/human-frozen.json work/human-first-run
```

이 도구는 **근거 검색 평가**입니다. 여러 단계 질문의 전체 자동 답변 성공률이나 LLM 정확도는 별도 평가가 필요합니다. 미등록 문서는 UNSUPPORTED_DOCUMENT로 남깁니다. 사람 작성 자료가 도착하지 않은 상태에서 AI 예시를 채워 넣지 않습니다.

## D. 제품 동일 모델 새 응답

새 배치 실행 후 실제 응답과 도구 실행 기록을 여기에 연결합니다. 현재 승인·실호출 전이므로 빈 상태입니다. 최대4개 설명과4개 제한형 도구 선택 과제이며, 실제 성공/실패를 그대로 검수합니다. 준비된 도구 응답을 모델 실행처럼 기록하지 않습니다.
