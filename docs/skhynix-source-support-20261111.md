# SK하이닉스 원문 파싱·근거 검색 보완 — 1단계

기준: `c9650a74c1692d6d7d4756ccfd993e317f309cf6` 이후 변경. [처음 실패한 결과](skhynix-human-baseline-20261111.md)는 그대로 보존했다. 삼성·현대차 분기 문서를 제품에 확대하는 작업으로 진행하지 않았다.

## 결과와 평가 경계

| 실행 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 공식 PDF의 지정 3쪽 → 파서 | 0/3쪽, 미지원 | 3/3쪽의 선택 행 18개 셀 추출 |
| 사용자 작성 질문 5개 → 근거 검색 | 5개 모두 근거 없음 | 5개 모두 요구 근거 셀 집합 검색, 계산 답변 0개 |
| 기존 수동 입력 음수 기준값 방어 | `NEGATIVE_BASE`, 계산값 `None` | 기존 기능 유지. 이번 PDF 추출 성공과 별도 기록 |

[실행 원본과 실제 MCP 입출력](../artifacts/skhynix-source-support-20261111/evaluation/report.json). 공식 PDF 파일의 SHA-256을 확인한 뒤 pypdf로 직접 읽었다. 텍스트 fixture를 원문 PDF 실행으로 세지 않았다. 인쇄 F-73/F-75/F-146은 PDF 뷰어 191/193/264쪽이다. PDF 전체 291쪽 중 3쪽의 지정 표·행만 지원한다.

18개 셀은 현금·재고·매출·매출원가·영업손익·DRAM·NAND·기타 제품·제품 합계의 2024·2023 열이다. 사용자 제출값에서 기존 AI 원문 대조로 작성한 10개 셀 주석과 금액·기간/기준일·연결·통화·단위·페이지·행·열을 재대조해 10/10 일치했다. 나머지 8개까지 새 사람이 검수한 것으로 세지 않는다. 제품별 합계는 구성 항목 합계와 대조했다.

질문·답안의 작성자는 프로젝트 작성자 본인이며, AI 미사용이라는 본인 확인을 기록했다. 이번 파서·검색 코드, 테스트와 실행은 AI 작업이다. 원래 질문 5개는 구현에 사용한 **개발 사례**이며 새 독립 평가셋이 아니다. 새 경계 질의와 변조 표 테스트도 AI가 작성했다. b의 새로운 검수나 새 외부 참가자 참여는 없다.

## 구현

- [source_evidence.py](../quarterguard/source_evidence.py)의 `parse_pdf()`는 정확히 등록한 PDF 해시만 받는다. `parse_page()`는 연결 표 제목, 2024·2023 열 순서, 백만 원 단위, 선택 행의 두 금액, 주석 24(2)의 제품 표 구간을 확인한다. 괄호 손실은 음수로 읽고, `23,467,3 19`처럼 PDF 추출 중 갈라진 마지막 쉼표 그룹만 제한적으로 복원한다. 모호한 금액·중복 행·추가 열·단위 변경은 거부한다.
- 현금·재고는 `period_kind=instant`, `as_of=12월31일`이다. `start/end`는 비워 둔다. 손익과 제품 매출은 `duration`과 1월1일~12월31일이다. 기존 분기 `Fact`나 12개월 실적으로 잔액을 변환하지 않는다.
- 원문 `Operating profit (loss)`, `Cash and cash equivalents` 등 행명과 표준 항목을 별도 저장한다. 제품 합계의 원문 행명이 비어 있다는 사실도 보존한다.
- `search_source()`는 명시적으로 선택한 문서의 조건 안에서 근거 후보만 찾는다. 기업·연결·KRW·백만 원이 질문 자체에 없으면 **문서에서 온 조건**이라고 표시한다. 원문 메타데이터를 유지하며 계산 결과를 반환하지 않는다.
- Q1은 기준 연도가 빠졌으므로 2024·2023 후보와 확인 안내를 표시한다. Q2는 재고 시점과 매출 기간을 나란히 표시한다. Q3은 DRAM과 같은 제품 표 합계를 연결한다. Q4는 음수 영업손익 해석 확인을 안내한다. Q5는 2024 재고·2023 매출을 유지하고, 매출원가는 **정의 확인용 관련 근거**로 따로 표시한다. 분모로 확정하지 않는다.
- 지원 밖 기업·연도·범위·통화·단위·분기·예상/조정·알 수 없는 조건은 거부한다. 날짜를 연말로 몰래 바꾸지 않는다. 공유 연도는 각 항목에 보존하고, 항목 뒤에 연도가 나오는 모호한 문법은 두 연도 후보와 확인 안내를 표시한다.

## 제품에서 확인

[공개 데모](https://quarterguard.onrender.com/) → **근거 검색** → **SK하이닉스 · 선택 문서의 근거 찾기**.

1. `현금은 2023년 말보다 얼마나 늘었나?`를 검색해 두 잔액과 기준일·기준 연도 확인 안내를 본다.
2. `2024년 DRAM 매출은 전체 매출의 몇 %인가?`로 44,731,664와 66,192,960백만 원, PDF264/인쇄F-146, 원문 행·연도 열을 확인한다. **비중 계산은 아직 하지 않는다.**
3. `2024년 재고가 2023년 매출의 몇 개월분인지 공시표만으로 단정할 수 있나?`에서 잔액/연간 실적 구분과 정의 확인 안내를 본다.
4. `2025년 매출`, `2024-06-30 cash`, `2024년 별도 매출`로 지원 밖 조건에서 이전 수치가 남지 않는지 확인한다.

새 API는 `/api/source-documents`, `/api/source-search?document_id=skh2024annual-in-2025oc&q=...`, `/api/source-cells/{id}`다. 기존 `/api/search`는 삼성 분기 검색 계약을 유지한다. `/api/facts` 192개와 분기 작업지 범위도 그대로다.

실제 MCP 확장 서버는 `python -m quarterguard.source_mcp_server`로 실행한다. `search_source_evidence` → `get_source_cell`을 5개 질문에 실제 stdio로 실행한 총18회 입출력을 기록했다. 고정된 호출 순서이며 LLM이 계획하거나 도구를 선택한 자율 에이전트가 아니다. 기존 `quarterguard.mcp_server`의 4개 도구와 고정된 과거 평가 코드 해시는 바꾸지 않았다.

## 검증과 실패 보존

- 최종 Python **279개 실행, OK, 1개 skip**, Node **14개 통과**. Python의 기존 Starlette/Pydantic 경고는 로그에 남긴다.
- PC1365×900·모바일390×844의 로컬 실제 FastAPI 연결: 근거 검색, 인쇄/PDF 쪽수 링크, 잔액/기간 구분, 미지원 조건 제거, 503 후 제거·복구, 기존 +6.7916% 비교 확인. 503만 주입했으며 정상 검색과 복구는 실제 서버다. [브라우저 결과·캡처](../artifacts/skhynix-source-support-20261111/browser/).
- 최초 전체 테스트는 기존 MCP 파일 변경 때문에 고정 평가 해시 검사14건이 실패했다. 과거 freeze나 응답을 수정하지 않고 새 서버 모듈로 분리했다. [초기 실패 로그](../artifacts/skhynix-source-support-20261111/verification/python-suite-initial.txt)와 최종 로그를 함께 보존한다.
- 별도 AI 코드 검토에서 명시 날짜 무시, 공유/후치 연도 연결, 제품 키워드에 의한 다른 매출 누락을 발견했다. 추가 연도 헤더 허용도 표 구조 거부 계약에 맞춰 수정했다. 각 실패를 테스트로 재현한 뒤 수정했다. 사람의 오류 발견·코드 수정 경험으로 기록하지 않는다.
- 기존 data/artifacts/validation-kit 파일의 내용 해시는 전부 보존한다. [보존 점검](../artifacts/skhynix-source-support-20261111/preservation.json).
- 새 유료 API 호출 **0회**, 새 LLM 생성 **0회**, 새 비용 **0**. 기존 청구액은 이번에 조회하지 않았다.
