# 제품형 공시 검토 화면

사용자 수정 요구: 배경색만의 문제가 아니라 전체 데모가 전형적인 AI 생성 화면처럼 보인다는 지적. 금융 문서 검토라는 실제 업무에 맞춰 다시 구성한다. 색상만 바꾼 차콜 시안은 폐기하고 배포하지 않는다.

## 조사에서 선택한 방향
실제 접근 가능한 문서 추출·검토 데모와 개발자 프로젝트를 확인했다. Alan Salomon의 공개 샘플 문서 검토 화면에서 목록→문서→추출 필드→검증 사유→내보내기 흐름을 확인했다. Intake AI, IRIS, Apryse, Ethan Haas, Document Intelligence의 공개 화면도 조사했으며 동작·차단·자료만 확인한 범위를 연구 문서에 구분한다. 홍보 화면의 큰 제목·KPI·그라데이션을 제품 작업 화면의 기본값으로 채택하지 않는다.

접근안: (1) 전체 색상 변경은 사용자 지적을 해결하지 못해 폐기. (2) 문서 업로드 제품은 현재 파서가 범용 파일을 처리하지 못하므로 허위 기능이 된다. (3) 실제 지원 자료를 고르고 수치 검토를 끝낼 수 있는 제품 작업 화면을 구현한다. 3번은 사용자의 재제작 지시를 해석한 구현자의 선택이며, 사용자가 특정 레이아웃을 선택했다고 주장하지 않는다.

## 화면과 기능
- 작은 전역 헤더, 문서 목록, 작업 제목/액션, 비교 결과와 근거를 중심으로 한 작업 영역. 큰 소개 영역·장식용 영문 오버라인·가짜 계정·가짜 업로드·가짜 알림 없음.
- 보고서 목록은 실제 2건과 수집 범위를 표시한다. 해당 자료에서 비교/근거 확인으로 진입한다.
- 기본 조건 요약은 항상 보이며 상세 A/B 조건은 접을 수 있는 설정 영역으로 이동한다.
- 6개 재무 항목, 문맥 불일치, 실제 MCP 검증, 원문 링크, 검색과 평가 기록은 유지한다.
- 선택 행의 검토 메모와 수동 확인 표시는 이 브라우저에 저장한다. 자동 검증 결과와 구분하고 정확한 두 근거 ID·비교 모드·문서 해시에 묶는다.
- CSV는 현재 결과·문맥·출처·수동 메모를 내보낸다. 실패/새 조건 로딩 시 내보내기를 차단한다. 메모의 수식 주입을 막는다.
- 원문 이미지처럼 꾸민 재구성 표를 제거하고 명시적인 추출 근거표로 표시한다. 발행사 PDF 직접 열기는 유지한다.
- 밝은 중성 작업 영역과 충분한 12–14px 본문, 제한적인 파란 액션, 명확한 포커스. 모바일에서도 값과 동작을 숨기지 않는다.

## 검증
실제 브라우저에서 자료 선택/조건 설정/행 근거/메모 저장·재접속/조건별 분리/CSV/오류·복구/키보드/모바일을 확인한다. 기존 31개 흐름을 새 UI에 맞춰 유지하고 새 동작에 대한 의미 있는 검증을 추가한다. 별도 AI 리뷰 후 PR/CI/배포 commit 대조 및 공개 응답 기반 재검사를 수행한다. 사람 사용성 테스트나 출시 수준 인증을 받았다고 주장하지 않는다.
