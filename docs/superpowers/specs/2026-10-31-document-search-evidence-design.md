# QuarterGuard evidence expansion design

User specification: nine-section request dated 2026-10-31. Continue the existing financial document review product, preserve all prior failure/evaluation/API records, and do not spend on model APIs or paid hosting without separate approval.

Implementation choice: improve the existing bounded parser and explicit-context retrieval rather than introducing a generative parser or autonomous planner. Maintain the curated 2024 public worksheet unless a newly parsed corpus passes canonical registration and product integration checks. New-period/company raw-PDF results are reported separately from fixture-assisted downstream diagnostics. This choice bounds false financial claims and deploy resource use.

Evaluation splits: 2024 existing development/regression; disclosed 2025 failures used for fixes; separately collected official documents and new questions frozen by an independent AI worker before post-fix execution. Human review remains false. Same-task AI independence is not independent expert curation. Preserve every previous artifact byte; new reports use versioned paths and baseline source hashes.

Retrieval: Korean/English normalization must retain company, metric, year/end-period, direct-quarter/YTD, scope, currency and explicit unit constraints. Unsupported/conflicting/missing conditions produce diagnostic clarification, never silently become a unique trusted answer. Separate candidate retrieval from verified answering. Benchmark lexical/dense/reranked configurations on identical case IDs and gold; report cost, model version/hash, cold-load vs warm latency, and weaker outcomes.

Explanation evaluation: replay the four recorded GPT outputs without a new paid call, add deterministic claim/citation checks and explicitly synthetic challenges. Automated checks are partial; free prose meaning requires human adjudication. No LLM judge or participant review will be invented.

User/customer and code review: prepare blank consent, tasks, review prompts and evidence templates. No actual participant, expert or customer completion claim. User must perform and confirm these stages.

Delivery: meaningful regression tests, real MCP traces and failure injection, browser flows via direct HTTPS where possible and separately labeled TLS-verifying relay, CI, main/Render/health/asset alignment, candid nine-part final report and application wording.
