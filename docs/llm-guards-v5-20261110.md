# 최신 설명·인용 방어의 실호출 평가 준비 — v5

**상태: 실행 준비 / 새 유료 호출 승인 대기.** 이 문서는 새 응답이나 개선 효과를 보고하지 않는다. 이전 두 배치 각8회 승인과 별개의 배치다. 2026-11-10 KST 기준 새 모델 호출0회, 새 사람 검수0건이다.

## 대상과 비교 조건

[직전 실제 응답8건](../artifacts/llm-followup-20261110/report.json)과 같은 모델·과제·도구 결과·오도 초안을 사용한다. 과제는 normal-qoq, normal-yoy, period-mismatch, scope-mismatch, unit-draft, no-evidence, conflicting-number-draft, citation-draft이다. 입력은 공개된 개발 사례이며 새 보류셋이 아니다. 두 오류를 수정하는 데 사용한 사례가 포함된다.

현재 `public_providers.build_payload()`가 생성하는 지침·표시 문맥·요청별 인용 ID 스키마를 그대로 사용한다. 평가를 위한 변경은 GPT-5.4 mini 고정 모델과 reasoning none, 기존 합성 오도 초안의 추가뿐이다. 공개 제품의 GPT-4.1 mini 성능이나 `/api/providers`·캐시 전체 흐름의 실호출 결과로 표현하지 않는다.

근거 입력은 11월9일 실제 MCP 실행 기록의 **재생**이다. 이번 준비에서 새 PDF를 파싱하거나 MCP 도구를 새로 실행하지 않았다. 승인 후 OpenAI가 생성하는 응답만 새 실호출이다. 프롬프트·문맥·스키마가 함께 바뀌므로 각 요소의 효과를 따로 추정하지 않는다.

## 승인을 요청할 실행 범위

|항목|제한|
|---|---|
|모델|`gpt-5.4-mini-2026-03-17`, reasoning `none`|
|대상|기존 개발 사례8건, 각1회|
|호출|최대8회, 자동 재시도0회, 오류 시 배치 중단|
|입력|회당 사전 제한7,500; 현재 고정 입력 최대7,100|
|출력|회당 `max_output_tokens=700`|
|요청 시간 제한|60초; 시간 초과 시 재시도 없이 기록하고 중단|
|공개 단가|입력 $0.75 / 출력 $4.50, 각각100만 토큰 기준|
|최대 추정|`8 × (7,500 × 0.75 + 700 × 4.50) / 1,000,000 = $0.0702`|
|승인 예산|$0.08, 세금·환율 제외|
|키|기존 GitHub Actions `OPENAI_API_KEY`; 키 값 조회·출력 없음|
|실제 청구액|미조회. 실행 후 토큰 사용량 기준 추정 비용과 분리|

입력 사전 제한은 직렬화한 전체 요청의 UTF-8 바이트 수+프레이밍 여유1,024로 계산한다. 공급자의 비공개 프레이밍까지 보장하는 API 입력 토큰 상한이 아니다. 실제 usage도 응답마다 대조하고 초과하면 추가 호출을 중단한다. 출력700은 API 요청 파라미터다. 무응답 등 사용량 미확인 실패는 추정 비용에 포함할 수 없음을 별도로 기록한다.

[공식 모델·단가](https://developers.openai.com/api/docs/models/gpt-5.4-mini)를 2026-11-10 확인했다. 이전6,500 상한은 새 문맥·스키마가 포함된 일부 요청보다 작아7,500으로 변경했다. 이 변경도 새 승인 범위에 포함된다.

[동결 입력](../data/llm-guards-v5-20261110/freeze.json)의 content SHA256:

`040115695a087729362bbe63f8abe78c426ed9e38d0e83ef589945c46c7f8231`

입력·코드·워크플로 해시가 다르면 호출 전에 중단한다. 워크플로는 수동 실행 전용이고 승인 입력 기본값은false다. 다른 dispatch가 있거나 재실행이면 키를 실행 단계에 전달하기 전에 차단한다. 로컬 실행도 명시적 승인 플래그와 새로운 시도 원장이 필요하다. 승인 플래그 자체는 사용자의 실제 동의를 대신하지 않는다.

## 자동 평가와 사람 검수

- 공급자의 JSON Schema 수용 여부, HTTP 오류·중단·사용량·지연시간을 보존한다. 400 오류가 나더라도 그 배치를 자동 재시도하거나 스키마를 완화해 재호출하지 않는다.
- 상태·값·문제 목록·정확한 순서의 근거 ID·필수 키를 도구 결과와 대조한다. 잘못된 ID를 고치지 않는다. 생성 성공 수와 제품 검사 통과 수를 따로 센다.
- 생성된 설명의 금액·백분율·기간·범위·단위·인라인 인용을 기존 규칙으로 검사한다. 문서·페이지와 단위 표현의 문자열 포함 여부는 표현 점검이며 의미 정확성 지표가 아니다.
- 직전 원응답과 새 원응답을 **같은 현재 감사 규칙**으로 다시 비교한다. 기존 보고서와 b의 참7·모호1, 구조필드7/8은 변경하지 않는다.
- 자유문장의 인과관계·부정·누락·인용 적합성은 사람이 다시 확인해야 한다. 과거 b의 판정을 새 응답에 복사하지 않는다. LLM-as-judge를 호출하지 않는다.
- 결과 파일은 `report.json`, `comparison.json`, 사례별 `*.response.json`, `attempts.jsonl`, 빈 `human-review.json`이다. 평가용 원응답에는 거부 대상도 남으며 공개 제품 화면에 자동 표시되지 않는다.

새 응답 확보 후 b에게 전달할 질문은 다음과 같다. 실제 수행·날짜·환경·도움·이 새 기록의 공개 동의는 그때 확인한다.

1. normal-yoy의 두 근거 ID가 도구 결과와 철자·순서까지 일치하는가?
2. scope-mismatch가 **연결·별도 차이만** 보류 이유로 설명하는가? 인접한 두 분기라는 사실을 잘못된 보류 이유로 덧붙이지 않았는가?
3. 8개 설명 각각의 금액·기간·범위·표시 단위·문서·페이지가 원문과 일치하는가? 숫자가 없는 보류 설명은 필요한 조건을 충분히 설명하는가?
4. no-evidence가 해당 검색 범위의 한계를 설명하고 실적 자체의 부재로 단정하지 않는가?
5. 각 사례를 참/거짓/모호/판단 보류로 기록하고, 문제 문구와 이유를 그대로 남길 수 있는가?

이 양식은 요청할 검수 항목이며 참여 결과가 아니다. 참가자 수 증가나 전문가 재확인 완료로 세지 않는다.
